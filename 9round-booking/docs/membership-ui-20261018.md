# 9ROUND WEB入会画面

入口は`9round-booking/membership/`です。2026年10月末までの申込書を元に、プラン選択・本人情報・内容確認を作成しています。カード入力は決済代行会社のUIへ接続する構成です。

現時点では確認用プレビューです。入会受付・決済・会員マスターへの登録・キャンペーン枠の確保は行いません。入力情報は画面のメモリだけで扱い、localStorage、sessionStorage、URL、ログ、ネットワークへ保存・送信しません。再読込で入力は失われます。既存の無料体験と会員予約の動作は変更しません。

キャンペーンはOneとHalfの合計で30名です。各30名ではありません。受付済み人数をまだ接続していないため、残り人数や受付成功を装う表示はしません。申込期限・開始日は今回の申込書に合わせ2026年10月31日まで。期限の判定は日本時間です。キャンペーン2種の3か月未満退会不可・期間内の差額精算・初期費用特典の条件、プラン変更期限、ペア等の通常プランへの移行、申込書裏面の注意事項を表示します。

氏名・カナ・生年月日・メール・郵便番号・住所・開始日を必須とし、電話・ファイターネームは任意です。ペア等のプランは相手の氏名、任意で6桁の会員番号を入力できます。入力の検査と修正、プランの切替、同意欄、署名確認があります。会員番号発行・グローブ受渡し等のスタッフ使用欄は顧客に記入させません。

初月会費の端数処理・決済日を本画面で推測して確定せず、固定費だけを月会費と分けて表示します。決済画面に進むボタンは無効にしてあります。

## 受付開始時に必要な接続

1. One・Halfで共通のキャンペーンIDと上限30名を受付サーバーで管理します。既存の紙・店頭申込人数も移行し、残数を確認します。フロントの表示だけで人数制限しません。
2. カード登録へ進む際、同時申込に対して共通枠を原子的に仮確保します。重複送信は同じ申込IDへ戻し、期限切れ・決済取消の仮枠を解放します。確保できなければ通常プラン等の確認へ戻し、選んでいないプランへ自動変更しません。
3. 会員ID・申込ID・決済側の顧客IDを紐付け、同じ利用者の顧客を重複作成しません。必要な情報だけを引き継ぎ、カード情報は9ROUNDのHTMLやGASへ送らず決済代行会社で扱います。
4. 初回会費・月会費の請求日、日割りと端数処理、25日以降の開始に対する翌月分、規約・個人情報の取扱い・必要な契約表示を確定し、サーバー計算の金額を決済画面へ渡します。
5. 決済完了はブラウザーの戻りURLだけでは確定しません。署名を検証できる受信サーバーで決済通知を処理し、入会・キャンペーン確定、会員マスター登録、確認メールを連携します。既存会員の照合はメールアドレスの自己申告だけを本人認証に使いません。

決済代行会社は未選定です。Stripe Checkout、Squareのホスト型決済画面などへ接続する想定で、特定の会社のSDK・秘密鍵は組み込んでいません。
