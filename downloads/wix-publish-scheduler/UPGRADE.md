# メール通知つきv0.2.0への更新

導入済みのWix HP更新予約アプリを、同じGoogleプロジェクト・同じウェブアプリURLのまま更新します。**新規インストーラーは再実行しません。**

## 更新前

登録済み予約の実行時刻より十分前に作業します。更新によりGoogleのメール送信権限が追加されるため、所有者の再承認が済むまで時間主導トリガーが実行できなくなる場合があります。予約時刻の直前は避け、まず予定日時を確認してください。

この更新処理は、Wixの公開API・テストメール・予約の取消を呼びません。コードのアップロードによって、既存予約・APIキー・サイトID・管理者の保存プロパティを初期化する処理もありません。

## アップデーター

既存の`google-project/.clasp.json`がある、最初にZIPを展開したフォルダーから`Update-Windows.ps1`を実行します。配布時のコミットIDとZIPのSHA-256を引数に指定します。引数はチャットで案内するコマンドに含めます。

アップデーターは次を行います。

1. コミットを固定したURLから配布ZIPを取得し、SHA-256を検証。
2. 同じGoogleプロジェクトの稼働中ソースを別フォルダーへ取得。
3. Wixアプリの関数・API呼出先と、既知の旧版／新版のソースハッシュを検査。不明な変更は上書きせず停止。
4. Google上に変更前のバージョンを保存。
5. コード・HTMLを更新。追加ファイルは保持し、元のマニフェストの設定を残してメール送信スコープを追加。
6. 同じプロジェクトの編集画面を開く。

`-NotificationEmail`引数に通知先を指定した場合、そのアドレスを所有者のGoogleプロジェクト内にだけ設定します。公開パッケージには実際の通知先を埋め込みません。`initializeWixPublisher`の再実行で通知を有効にします。後で手動変更した通知設定は、同じアドレスで初期設定を繰り返しても上書きしません。

PowerShell 7/Linuxの模擬環境で、既存設定と追加ファイルの保持、コード差分・別プロジェクト・破損ZIPでの停止を検証しています。実際のWindowsとGoogleへの反映は、実行後の表示を確認して進めます。

## Google側で必要な操作

1. `initializeWixPublisher`をもう一度実行し、メール送信権限を承認します。この関数は既存の予約やAPIキーを消しません。
2. 「デプロイ」→「デプロイを管理」→現在のウェブアプリの鉛筆マーク→「新バージョン」→「デプロイ」。アクセス設定は「自分のみ」を維持します。
3. 既存のウェブアプリURLを再読み込みし、「更新結果のメール通知」が表示されることを確認します。
4. 通知先を入力して「更新結果をメールで受け取る」をオンにし、「メール通知を保存」。予約済みでもこの設定は変更できます。
5. 「通知テストを送る」を押し、受信を確認します。この操作ではHPを更新しません。
6. 既存の更新予約の日時が維持されていることを確認します。

成功・公開失敗・結果不明・期限切れを通知します。通知を有効にする前に完了していた過去の履歴や、取消は自動でメールしません。

## 送信失敗時

HPの処理結果を先に保存し、メール送信結果を別欄に記録します。メール送信が失敗・不明でもHPを再公開しません。メールも自動で再送せず、実行履歴に送信失敗／確認が必要と表示します。

送信待ちのメールがある間は、その送信処理を続けるためのトリガーを維持します。送信途中で処理が中断された場合は結果不明として扱い、二重送信を避けます。
